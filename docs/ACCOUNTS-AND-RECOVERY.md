# Accounts and recovery (0.5.0-dev)

- The installation root shows employee login. Administration is /admin/; admin.php remains an authenticated controller for compatible installations.
- Company login accepts the configured domain or a local part. Personal mode accepts an external email registered by an administrator, using the TNL password. It is not open self-registration and does not authenticate arbitrary Gmail/Outlook accounts. Mailbox connection requires provider-supported credentials; OAuth is not implemented.
- Administration /admin/?page=users edits display names/internal addresses and assigns multiple existing provider mailboxes. Editing an assignment revokes old-user access immediately. SMTP and IMAP usernames/passwords can differ. Secrets are encrypted with the existing storage/external-mail.key, which must be backed up together with SQLite.
- TLS uses the system CA trust store and verifies server names. Saved server settings are reused. Custom CA upload, certificate pinning and OAuth are not implemented. SMTP supports implicit TLS 465 or mandatory STARTTLS 587; IMAP uses TLS 993.
- Archive and trash are provider folders TNL Archive and TNL Trash. MOVE capability and matching UIDVALIDITY are required. Deletion from TNL Trash first stores complete raw MIME in protected SQLite, then uses UIDPLUS individual UID EXPUNGE; global EXPUNGE is never used.
- Recovery is /admin/?page=trash, restoring to TNL Recovered in the original configured mailbox. A changed/missing mailbox prevents recovery to a different address. Maximum 1 MiB per message, 250 MiB total; limit or preservation failure blocks deletion. No automatic purge. Raw MIME includes attachments, is not sent to the browser, and is protected by the existing storage directory access rules. Recovery copies are not encrypted at rest beyond host protections.
- A device PIN is configured at lock.php after re-entering the current TNL password. A random 256-bit token is stored in an HttpOnly SameSite Strict cookie; only its hash and a password-hashed 6-digit PIN are stored in SQLite. Device expires in 30 days and is revoked after five failed PIN attempts. Employee password reset/version change revokes the device. Server-side locking applies after 15 minutes idle; pages request a refresh to the lock screen. Forget-device closes the session. Manual logout removes the device token. Phone QR/WebAuthn unlock is not implemented.
- Internal local mail retains its earlier behavior. Archive/recovery actions in this release apply to external IMAP mail.
- Tests use synthetic in-memory SQLite, protocol fakes and isolated local HTTP fixtures; no real messages are sent or deleted by the tests.
