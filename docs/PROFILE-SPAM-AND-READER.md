# Profile, spam and reader (0.7.0-dev)

Profile is /profile.php. Employee display names can be edited; username, role, company address and assigned mailboxes remain admin-controlled. Every principal can associate up to 20 external personal accounts. Connections are stored under personal:ID with the existing AES-GCM key and independent usernames/secrets. Personal IDs are AUTOINCREMENT to avoid reusing old sent/recovery ownership. Personal accounts can be unlinked after CSRF, current TNL password and explicit checkbox confirmation. Unlink removes only local connection/secret, not the provider mailbox or retained sent/recovery copies. Corporate addresses, internal identities and assigned company accounts cannot be self-unlinked. Current sessions, active state, credential version and PIN gates protect profile and printing.

External account selector now includes assigned, personal and primary connections. Switching and print lookup validate exact ownership. The business primary address cannot be changed into a deletable personal connection.

Spam rules are scoped to principal and a single parsed From address. Company-domain senders, internal user addresses and assigned corporate mailbox addresses cannot be blocked. Sender identity is based on the visible From header; this is not SPF/DKIM/DMARC validation. This release does not replace hosting anti-spam or an Internet MTA. Marking spam stores the local rule and requests safe UID MOVE into TNL Spam, with UIDVALIDITY validation. If movement fails, the rule remains and the user is told. Future inbox pages filter blocked senders and attempt up to three safe moves per page. Route supervision records filtered/quarantined outcomes. No global EXPUNGE is used. No-spam and profile unblock remove the principal's rule. Company protections also override stale rules.

Internal and external inbox rows use one compact row with actions overlaid on hover, focus, checkbox selection or the ellipsis button. Local internal messages gain per-participant archive flags, without changing the other participant's copy.

Received MIME keeps a safe HTML alternative and bounded inline PNG/JPEG/GIF/WebP CID images. The original plain-text parser is retained as a fallback. HTML is sanitized to an allowlist, active content/source styles/dimensions and empty spacer blocks are removed. It is displayed in a sandboxed iframe without script permission and with a restrictive CSP. Inline images render immediately; remote HTTPS images require an explicit user click and use no referrer. Reader height follows sanitized content, avoiding newsletter spacer heights. The existing raw-message read limit remains 1 MiB. Message size/depth/image limits still apply.

Print/PDF: authenticated /print.php reads only a participant's internal message or the exact owner of an external account/sent copy. It renders escaped text or the same sanitized HTML/CID images. The button invokes the browser's print dialog; users choose a printer or Save as PDF. No server-side PDF file is generated, and independent attachments are not included.

Validation: unit tests for personal account isolation, corporate deletion/spam protections, per-user spam, internal archive isolation, four MIME CID images, active-content/remote-image filtering and oversized spacer removal. Isolated HTTP tests cover account linking/switching/unlink, company protection, spam/no-spam and print views. Browser checks on fictitious data show 53px compact rows unchanged when selected, four loaded 128x72 CID images in a 492px reader, and print/profile views. Original user messages and live spam/delete actions were not exercised.
